Implement Pack Best Principles

This file is append-only operating memory for the implement playbook. Every meaningful run should add reusable lessons here.

Seed Principles

  • Use the smallest tier that can honestly finish and verify the job.
  • Separate obvious edits from work that needs reasoning; run both lanes in parallel when independent.
  • Put code cognition on headless codex exec; keep Workflow agents as cheap glue unless a single final synthesis needs more taste.
  • Rate every plan, implementation, verifier result, and checkpoint out of 100.
  • Blocked verification is not a pass. Document the blocker and cap the rating honestly.
  • Checkpoint first; do not auto-commit unless explicitly asked.

Transport hardening under live load

  • Put one component in charge of retries. Layered retries turn one inference POST into an unbounded cost and duplicate-work risk.
  • A shadow-only observer should not sit inline with production traffic. Run it off-path, or make every hot-path side effect bounded, asynchronous, and fail-open.
  • Drain long-lived streams to zero before reloading a local inference gateway; prove the new PID, loaded environment, socket topology, and post-reload log window.
  • Scheduler priority protects transport responsiveness under build pressure, but it does not replace removing architectural choke points.
  • An independent verifier below the pass floor is a repair trigger, not a reporting footnote. Fix the blocker, reload safely, and re-score.
